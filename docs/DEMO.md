# Демо Burrow Next

Новый сценарий показывает подготовку к игре: версия и ник, выбор сборки, настройки, инструкция для совместной игры и возврат к запуску. Источник действий, реплик и фактических границ глав - [record.mjs](../scripts/demo/record.mjs). Готовый новый ролик ещё не снят и не проверен.

[Прежний ролик с озвучкой](assets/demo/burrow-next-demo.mp4) относится к Next.6 и коду `f74c19b783a8c78440824260ed752c5d16bb354e`; его данные остаются в [provenance](assets/demo/provenance.json). Он не показывает новый дизайн. Запись использует настоящее окно stock Electron с renderer/main, а не установленный NSIS-пакет; ограничение следует из [способа запуска](../scripts/demo/record.mjs).

## Сценарий и оформление

| Глава | Действие в настоящем интерфейсе | Озвучка |
| --- | --- | --- |
| Версия и ник | Выбрать Minecraft 1.21.1, ввести Steve | Перед игрой выбираем версию Minecraft и ник. Сейчас покажем подготовку, без запуска игры. |
| Сборки | Выбрать «Своя сборка», открыть детали | В библиотеке выбираем свою сборку. В деталях можно проверить версию и загрузчик. |
| Настройки | Открыть настройки сборки, затем настройки приложения | Настройки сборки открываются здесь. Общие настройки лаунчера находятся в отдельном разделе. |
| Игра с друзьями | Открыть «Вместе», раскрыть инструкцию | Для игры с друзьями откройте «Вместе». В инструкции есть шаги для хозяина мира и гостя. Подключение здесь не проверяем. |
| Вернуться к игре | Вернуться на экран запуска | Возвращаемся к игре. Это демонстрационные сборки: игровые файлы не установлены. |

Сценарий, синтетические данные и selectors заданы в [record.mjs](../scripts/demo/record.mjs). Исходное окно 1280 × 900 сохраняется целиком; [assemble.py](../scripts/demo/assemble.py) добавляет снизу полосу 110 px. Итоговый кадр 1280 × 1010. Тёплый угольный фон, светлый песочный текст и зелёные квадратные отметки глав поддерживают игровой характер. Заголовок 28 px и подпись 26 px читаются без пиксельного шрифта; по умолчанию Windows использует установленный Segoe UI, остальные системы - DejaVu Sans. Доступность конкретного шрифта и читабельность в готовом видео требуют визуальной проверки.

Подписи повторяют полные реплики в пределах двух строк и не перекрывают интерфейс. Движение задают настоящие действия и курсор. Монтаж сохраняет последовательность экрана, без стоп-кадров, фальшивого геймплея и декоративных переходов. Длительность определяется записью; фиксированной сетки на 45 секунд больше нет. Всё оформление и ограничения длины подписи находятся в [assemble.py](../scripts/demo/assemble.py).

## Переснять

Нужны сборка проекта, Electron/Playwright, Python 3.11+, `ffmpeg`/`ffprobe` с фильтром libass `subtitles` в PATH. Для голоса требуется [requirements.txt](../scripts/demo/requirements.txt). Голос по умолчанию - `ru-RU-SvetlanaNeural`, темп `+5%`; в Edge TTS отправляется только публичный текст сценария. Интернет нужен для новых реплик; кеш учитывает текст, голос и темп. `--silent` собирает подписи без TTS, `--check` проверяет metadata и доступность инструментов без рендера или сетевого запроса. Это поведение задаёт [assemble.py](../scripts/demo/assemble.py).

Сначала собрать актуальный продукт, затем выбрать новый каталог для каждого захвата:

```powershell
npm run build -- --publish never
node scripts/demo/record.mjs work/demo-retake
python scripts/demo/assemble.py work/demo-retake --check
python scripts/demo/assemble.py work/demo-retake
```

Если `edge_tts` не установлен, использовать отдельное окружение:

```powershell
python -m venv work/demo-venv
work/demo-venv/Scripts/python.exe -m pip install -r scripts/demo/requirements.txt
work/demo-venv/Scripts/python.exe scripts/demo/assemble.py work/demo-retake
```

На macOS/Linux заменить путь Python окружения на `work/demo-venv/bin/python`. Нативная запись на этих платформах не проверена. Без озвучки:

```powershell
python scripts/demo/assemble.py work/demo-retake --silent
```

[Запись](../scripts/demo/record.mjs) создаёт отдельный временный профиль с тремя синтетическими сборками Minecraft 1.21.1/Vanilla и лимитом памяти 6 ГБ. Каталоги игры пустые. Она не нажимает запуск, не скачивает игру, не входит в настоящий аккаунт и не соединяет игроков. При загрузке приложение может получать публичные списки версий. Новая запись останавливается, если в выбранном каталоге уже есть metadata. После закрытия Electron удаляется только созданный скриптом профиль.

Запись сохраняет raw WebM, снимки и `demo-recording.json`: фактический Git HEAD, признак незакоммиченных изменений, размер окна, ошибки renderer и границы глав. Границы озвучки и подписи берутся из этих глав; слишком длинная реплика останавливает сборку вместо растягивания кадров. Старые metadata без схемы 2 требуют пересъёмки. Сборщик всегда заново кодирует немой видеоряд, поэтому прежний `burrow-demo.mp4` не подменяет новый захват. См. [record.mjs](../scripts/demo/record.mjs) и [assemble.py](../scripts/demo/assemble.py).

Результат с голосом - `work/demo-retake/burrow-demo-voice.mp4`, без голоса - `burrow-demo.mp4`. Файл `chapters.ass` содержит подписи, `voices/timeline.json` - технические проверки, хеш результата и границы реплик. Подготовительный участок raw-записи отрезается по её длительности и длительности сценария с запасом 0,15 секунды; точное совпадение реплики и действия проверяется при просмотре. Появление полосы означает повторное кодирование исходной записи; голос добавляется с копированием готового видеопотока. См. [assemble.py](../scripts/demo/assemble.py).

## Проверка перед публикацией

Сборщик проверяет схему и последовательность глав, наличие libass, аудиодорожку, длительность и полное декодирование результата. `humanListening=false` и `visualReview=false` в таймлайне явно оставляют ручную проверку незавершённой. Успешный прогон не подтверждает запуск Minecraft, вход Microsoft, связь между двумя компьютерами или редакционную готовность.

Посмотреть и прослушать весь ролик: заголовки и реплики должны соответствовать действиям, все подписи помещаться в полосу, курсор не закрывать важные детали, инструкции оставаться читаемыми. Особенно проверить обе стороны границы каждой главы и начало после обрезки. После изменения UI повторно проверить selectors. Перед публикацией проверить отсутствие личных имён, аккаунтов, путей, миров и переписок.

Только после нового захвата и ручной проверки обновить опубликованный MP4 и provenance с его фактическим хешем и исходным SHA. Запись с `dirty=true` сама по себе не подтверждает соответствие видео одному коммиту; для публикации записать чистую проверенную сборку. Старому ролику нельзя приписывать новый HEAD. В рамках подготовки сценария опубликованные видео и provenance не изменяются.
